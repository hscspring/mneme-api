## 验证与复现

仓库根目录执行（manifest 核验只用标准库）：

```bash
python3 evaluation/verify_delivery.py
uv lock --check --offline
.venv/bin/python -m pytest -q
git diff --check
```

本次现有环境 API 测试 11 passed；唯一 warning 是 Starlette TestClient 的 httpx 弃用提示。
`uv.lock` 原先仍指向旧版本，本次重新解析为 API 0.3.1 / core 0.10.2。两份 lock 生成时间
不同，部分间接依赖版本不同；安装选择 README 的 requirements 流程或
`uv sync --extra test --extra evaluation`，不要混用两种锁定结果。

获准访问原始日志后，可重新生成脱敏数值文件，输出目标必须不存在：

```bash
python3 evaluation/archive_search_metrics.py \
  /path/to/original/search-metrics.jsonl /path/to/new/sanitized.jsonl
```

程序只读原始日志，输出原始 SHA256 和全窗口统计。第二轮逐条数值已入库，无需访问服务器
即可重新计算 history bins。历史 projector、fingerprint、channel diagnostic、migration 和
gate 脚本需要搭配对应报告的 core 版本，不保证在最新 core 上直接可运行。

Reader/Judge 复跑需要从 manifest 来源取回同 SHA256 的 baseline/candidate contexts，
并在独立 core checkout 中使用对应版本评测器；`evaluation/archive/core_eval/` 保存当前
评测器快照，完整参数见源码。例如：

```bash
PYTHONPATH=/path/to/Mneme python -m eval.memops_package_answer_eval \
  --baseline-contexts /path/to/baseline.jsonl \
  --candidate-contexts /path/to/candidate.jsonl \
  --benchmark longmemeval --input-token-budget 24000 \
  --repetitions 3 --workers 4 --env /path/to/private/reader-judge.env \
  --output /path/to/new/report.json
```

冻结评测使用 Qwen3.6 Reader / MiniMax-M3 Judge，凭据由操作者提供；模型服务和采样会波动，
因此精确核验依赖本次已提交的 predictions。历史源码按报告的 core tag/API commit 恢复。
